# 3 分钟 Demo 脚本

## 0:00-0:25 问题

“企业 SOC 最难处理的不是没有告警，而是告警太多、上下文不足。分析师需要同时看 SIEM、EDR、NDR 和威胁情报平台，很多时间花在复制 IOC、查情报和写结论上。”

## 0:25-0:55 方案

“这个 POC 把流程压缩成五步：告警接入、IOC 提取、情报富化、风险评分、处置建议。输入是脱敏后的样例告警，输出是一份可以直接给客户看的事件报告。”

## 0:55-1:45 演示

1. 展示 `data/sample_alerts.jsonl`，说明样例告警来自 Wazuh、Suricata、EDR、WAF 和邮件网关。
2. 运行 `PYTHONPATH=src python -m alert_triage.cli`。
3. 打开 Dashboard，展示高危、中危、低危和 IOC 命中率。
4. 选择一条 C2 告警，说明评分来自“高危告警 + 高价值资产 + 恶意情报 + C2 标签”。
5. 展示处置建议和 Markdown 报告。

## 1:45-2:30 业务价值

“这个 POC 的价值不是替代分析师，而是把重复的 IOC 查询、风险初筛和报告整理自动化，让分析师把时间放在确认资产、判断影响和推进处置上。”

## 2:30-3:00 边界与下一步

“当前使用本地脱敏数据，不接真实客户环境。下一步可以接 Wazuh、Suricata 和企业资产库，也可以把查询能力封装成 MCP 工具，服务 Agent 化研判流程。”
