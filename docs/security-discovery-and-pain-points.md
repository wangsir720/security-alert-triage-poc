# 安全需求调研与痛点识别

## 目标

售前不能只问“你需要什么产品”，而要确认客户为什么在当前阶段需要安全建设，以及不解决问题会带来什么影响。

## 调研框架

### 1. 业务场景

- 客户所属行业、业务规模和关键业务系统；
- 是否存在重保、监管检查、等保测评或上级考核；
- 安全事件对业务、客户和品牌的影响；

### 2. 当前安全架构

- 已有防火墙、IPS、WAF、EDR、NDR、SIEM 等能力；
- 日志是否集中采集，威胁情报是否接入；
- 资产台账和 CMDB 是否完整；
- 告警由谁接收、如何分诊、如何闭环；

### 3. 当前痛点

- 告警数量过大，处置优先级不清晰；
- 缺少威胁情报上下文，IOC 查询依赖人工；
- 多设备告警割裂，无法还原攻击链；
- 误报率高，安全团队人力被重复工作占用；
- 缺少可量化的运营指标和管理报告；

### 4. 价值与下一步

- 需要优先解决的安全问题；
- 期望的 POC 场景和成功标准；
- 项目周期、预算、决策人和采购流程；
- 试点成功后如何扩展到更多资产和业务。

## 售前输出

每次调研后至少输出：

1. 客户现状图；
2. 安全痛点优先级；
3. 方案能力映射；
4. POC 范围和验收标准；
5. 下一步行动和责任人。

## 售前表达示例

> 我会先确认客户现有安全能力和业务场景，再把“告警太多、误报高、处置慢、合规压力大”等表象拆成可验证的痛点，最后用 POC 验收标准把方案价值落到具体指标。
